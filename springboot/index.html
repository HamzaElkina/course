Travaux pratiques : Application Web MVC avec Spring Boot

Thème : Gestion des inscriptions des étudiants

JSP · JSTL · Validation des formulaires · HandlerInterceptor

Durée indicative : 2 à 3 heures Niveau : intermédiaire Travail : individuel

Contexte et objectifs

Vous devez développer une application Web MVC permettant de consulter une page d’accueil et d’inscrire des étudiants. L’application utilisera Spring Boot MVC pour le contrôleur, JSP pour les vues, JSTL pour le rendu conditionnel et les fonctions de présentation, Jakarta Bean Validation pour contrôler les formulaires, ainsi qu’un intercepteur pour observer le cycle de traitement des requêtes.

Compétences visées

  • Créer un contrôleur Spring MVC et transmettre des données à une JSP
  • Utiliser JSTL Core : c:if, c:choose, c:when, c:otherwise, c:set et c:url.
  • Formater une date et manipuler une chaîne avec JSTL Functions.
  • Créer et valider un objet de formulaire avec @Valid et BindingResult.
  • Afficher les erreurs de validation dans une JSP.
  • Implémenter et enregistrer un HandlerInterceptor.
Compatibilité : les exemples ci-dessous ciblent Spring Boot 3 et Java 17 ou plus récent. Utilisez les imports jakarta.validation.*. JSP nécessite une configuration et des dépendances compatibles avec le conteneur Servlet ; un déploiement WAR sur Tomcat est généralement le choix le plus sûr avec Spring Boot. Les URI JSTL ci-dessous correspondent à JSTL 1.2 ; si votre projet utilise Jakarta Tags 3.x, adaptez les dépendances et les URI à cette version.

Préparation du projet

1. Dépendances principales

Créez un projet Spring Boot avec Spring Web MVC et la validation. Ajoutez les dépendances JSP/JSTL compatibles avec votre version de Spring Boot et du conteneur. Exemple de dépendance de validation :

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>

Pour un projet JSP, prévoyez également le moteur JSP (par exemple Jasper dans un environnement Tomcat compatible), JSTL et le packaging adapté.

2. Configuration des vues JSP

Placez les vues dans src/main/webapp/WEB-INF/jsp/, puis configurez application.properties :

spring.mvc.view.prefix=/WEB-INF/jsp/
spring.mvc.view.suffix=.jsp

3. Organisation indicative

Partie 1 — JSP et JSTL : conditions, variables, dates et fonctions

Objectif Créer une page d’accueil dynamique qui utilise les balises et fonctions JSTL demandées.

Travail à réaliser

  1. Créer une route GET /accueil dans un contrôleur Spring MVC.
  2. Utiliser c:url pour naviguer vers une deuxième page JSP (N'oublier pas d'ajouter le nouveau chemin dans un controlleur).
  3. Transmettre à la vue les attributs nom, date et filiere. Utiliser par exemple un nom contenant des majuscules et une chaîne contenant un caractère à remplacer.
  4. Dans accueil.jsp, déclarer les bibliothèques JSTL nécessaires.
  5. Utiliser c:set pour définir une variable message contenant « Bienvenue » et afficher cette variable.
  6. Utiliser c:if pour afficher un message si le nom n’est pas vide.
  7. Utiliser c:choose, c:when et c:otherwise pour afficher un message différent selon la filière transmise par le contrôleur.
  8. Afficher la date au format jour/mois/année avec fmt:formatDate.
  9. Afficher la longueur du nom avec fn:length(), le nom en minuscules avec fn:toLowerCase() et une version transformée de la filière avec fn:replace().

Déclarations des bibliothèques JSTL (syntaxe JSTL 1.2)

<%@ taglib prefix="c"
    uri="http://java.sun.com/jsp/jstl/core" %>

<%@ taglib prefix="fmt"
    uri="http://java.sun.com/jsp/jstl/fmt" %>

<%@ taglib prefix="fn"
    uri="http://java.sun.com/jsp/jstl/functions" %>

Exemple à intégrer dans la JSP

<c:set var="message" value="Bienvenue"/>
<p>${message}, ${nom}</p>

<c:if test="${not empty nom}">
    <p>Le nom a été renseigné.</p>
</c:if>

<c:choose>
    <c:when test="${filiere == 'Informatique'}">
        <p>Filière informatique.</p>
    </c:when>
    <c:when test="${filiere == 'Réseaux'}">
        <p>Filière réseaux.</p>
    </c:when>
    <c:otherwise>
        <p>Autre filière.</p>
    </c:otherwise>
</c:choose>

<p>Date : <fmt:formatDate value="${date}"
    pattern="dd/MM/yyyy"/></p>

<p>Longueur du nom : ${fn:length(nom)}</p>
<p>Nom en minuscules : ${fn:toLowerCase(nom)}</p>
<p>Filière transformée :
    ${fn:replace(filiere, ' ', '-')}</p>
À vérifier : l’attribut date transmis à fmt:formatDate doit être un objet date compatible, par exemple java.util.Date. La fonction fn:replace() remplace ici les espaces par des tirets.

Questions

  1. Quelle est la différence entre c:if et c:choose ?
  2. Quel est le rôle de c:set ?
  3. Pourquoi utilise-t-on les préfixes c, fmt et fn ?
  4. Quelle valeur est renvoyée par fn:length(nom) ?
  5. Que se passe-t-il si la filière ne correspond à aucun des deux cas prévus ?

Partie 2 — Formulaire d’inscription et validation

Objectif Créer un formulaire d’inscription d’étudiant avec quatre champs textuels et un choix de sexe par boutons radio, puis afficher les erreurs de validation.

Champs obligatoires

ChampType de saisieRègles de validation minimales
NomTexteObligatoire, entre 2 et 50 caractères
PrénomTexteObligatoire, entre 2 et 50 caractères
TéléphoneTexteObligatoire, format marocain défini par une expression régulière et expliqué dans le rapport
E-mailE-mailObligatoire et format valide
SexeRadio buttonsUn choix obligatoire, par exemple « Féminin » ou « Masculin »

A. Créer la classe EtudiantForm

Créez une classe Java contenant les cinq propriétés, les getters et setters nécessaires, et les contraintes de validation. Utilisez notamment :

  • @NotBlank pour le nom, le prénom, le téléphone et l’e-mail ;
  • @Size pour limiter la longueur du nom et du prénom ;
  • @Email pour l’e-mail ;
  • @Pattern pour le téléphone ;
  • @NotBlank ou une contrainte adaptée pour le sexe.

Ajoutez un message explicite à chaque contrainte, par exemple @NotBlank(message = "Le nom est obligatoire").

B. Créer le contrôleur

Dans InscriptionController, implémentez :

  • GET /inscription : afficher un formulaire vide ;
  • POST /inscription : valider et traiter les données soumises ;
  • en cas de succès, afficher une page de confirmation reprenant les données validées.

La méthode POST doit utiliser les éléments suivants, dans cet ordre logique :

@Valid @ModelAttribute("etudiant") EtudiantForm etudiant,
BindingResult result

if (result.hasErrors()) {
    return "inscription";
}
  1. @Valid déclenche l’évaluation des contraintes de l’objet.
  2. BindingResult contient les erreurs de binding et de validation.
  3. result.hasErrors() indique si des erreurs ont été détectées.
  4. return "inscription" réaffiche le formulaire avec les erreurs.
Placez BindingResult immédiatement après le paramètre annoté avec @Valid. Si des erreurs existent, ne poursuivez pas vers l’enregistrement.

C. Créer la vue inscription.jsp

Utilisez les balises Spring Form :

  • <form:form> pour le formulaire ;
  • <form:input> pour nom, prénom, téléphone et e-mail ;
  • <form:radiobutton> pour les deux choix de sexe ;
  • <form:errors> pour afficher l’erreur associée à chaque champ.

Déclaration JSP :

<%@ taglib prefix="form"
    uri="http://www.springframework.org/tags/form" %>

Exemple de structure à compléter :

<form:form modelAttribute="etudiant"
           method="post"
           action="${pageContext.request.contextPath}/inscription">

    <label>Nom</label>
    <form:input path="nom"/>
    <form:errors path="nom" cssClass="erreur"/>

    <!-- Ajouter les champs prénom, téléphone et e-mail -->

    <label>Sexe</label>
    <form:radiobutton path="sexe" value="Féminin"/> Féminin
    <form:radiobutton path="sexe" value="Masculin"/> Masculin
    <form:errors path="sexe" cssClass="erreur"/>

    <button type="submit">S'inscrire</button>
</form:form>

Tests à effectuer

  1. Soumettre le formulaire sans remplir aucun champ.
  2. Saisir un nom d’un seul caractère.
  3. Saisir un e-mail incorrect.
  4. Saisir un numéro de téléphone ne respectant pas le format retenu.
  5. Soumettre un formulaire valide et vérifier la page de confirmation.
  6. Vérifier que les champs déjà saisis restent renseignés après une erreur.

Partie 3 — Intercepteur Spring MVC

Objectif Créer un HandlerInterceptor qui journalise les requêtes et observe les différentes étapes du traitement MVC.

A. Créer JournalInterceptor

La classe doit implémenter HandlerInterceptor et redéfinir les trois méthodes suivantes :

MéthodeTravail demandé
preHandle()Afficher l’URL demandée et l’heure de début ; retourner true pour continuer.
postHandle()Afficher un message indiquant que le contrôleur a terminé son traitement avant le rendu de la vue.
afterCompletion()Afficher un message de fin de traitement et, si possible, la durée totale de la requête.

Signature indicative :

public class JournalInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler) throws Exception {
        // Journaliser l'URL et l'heure de début
        return true;
    }

    @Override
    public void postHandle(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler,
            ModelAndView modelAndView) throws Exception {
        // Journaliser la fin du contrôleur
    }

    @Override
    public void afterCompletion(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler,
            Exception ex) throws Exception {
        // Journaliser la fin du traitement MVC
    }
}

Ajoutez les imports nécessaires depuis jakarta.servlet et org.springframework.web.servlet.

B. Enregistrer l’intercepteur dans WebConfig

Créez une classe de configuration qui implémente WebMvcConfigurer. Elle doit enregistrer l’intercepteur avec addInterceptors.

@Configuration
public class WebConfig implements WebMvcConfigurer {

    private final JournalInterceptor journalInterceptor;

    public WebConfig(JournalInterceptor journalInterceptor) {
        this.journalInterceptor = journalInterceptor;
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(journalInterceptor)
                .addPathPatterns("/**")
                .excludePathPatterns("/css/**", "/js/**");
    }
}

Vérifiez que l’intercepteur est bien détecté par Spring, par exemple en annotant sa classe avec @Component.

C. Vérifications

  1. Accéder à la page d’accueil et observer les logs.
  2. Afficher le formulaire d’inscription.
  3. Soumettre un formulaire invalide puis un formulaire valide.
  4. Comparer l’ordre d’appel de preHandle(), postHandle() et afterCompletion().
  5. Expliquer pourquoi postHandle() peut ne pas être appelé lorsqu’une exception interrompt le traitement du contrôleur.
Limite : un intercepteur Spring MVC intervient dans le cycle des gestionnaires MVC. Il ne remplace pas un filtre Servlet ni les mécanismes d’authentification et d’autorisation de Spring Security.
