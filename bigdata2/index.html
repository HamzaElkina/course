Big Data 2 · TP1

Installation et déploiement d’un cluster Apache Spark

Ubuntu 26.04 LTS · Un Master et deux Workers sur un réseau local · Application PySpark d’analyse d’un million d’étudiants

Durée indicative : 1 à 3 heures Niveau : initiation Architecture distribuée
Sommaire du TP
1. Objectifs 2. Architecture 3. Préparation des serveurs 4. Installer Spark 5. Réseau et communication 6. Configurer Master et Workers 7. Démarrer le cluster 8. Préparer le dataset 9. Application PySpark 10. Exécuter l’application 11. Arrêt du cluster

1. Objectifs du TP

Installer Apache Spark sur un serveur Ubuntu 26.04 LTS, configurer un cluster distribué composé d’un Master et de deux Workers situés sur des machines distinctes du même réseau local, puis développer une application PySpark pour analyser un dataset de 1 000 000 d’étudiants.

À la fin du TP, l’étudiant devra être capable de :

  • Installer Java, Python et Apache Spark sur Ubuntu.
  • Configurer la communication entre les nœuds d’un cluster Spark.
  • Déployer un Master et deux Workers sur trois machines.
  • Soumettre une application PySpark au cluster.
  • Effectuer des calculs statistiques et des agrégations sur un grand volume de données.
  • Observer l’exécution distribuée et interpréter les résultats.

À retenir : le Master coordonne les ressources ; les Workers hébergent les executors qui effectuent les calculs. Le processus driver pilote l’application. Deux Workers ne garantissent pas à eux seuls un temps d’exécution deux fois plus court.

3. Préparation des trois serveurs

3.1 Identifier les adresses IP

Sur chaque machine, exécuter :

hostname
ip -br address
RôleNom de machineAdresse IP d’exemple
Masterspark-master192.168.1.10
Worker 1spark-worker1192.168.1.11
Worker 2spark-worker2192.168.1.12

Utiliser des adresses IP fixes ou des réservations DHCP. Sur les trois machines, modifier /etc/hosts :

sudo nano /etc/hosts

Ajouter les lignes suivantes :

192.168.1.10 spark-master
192.168.1.11 spark-worker1
192.168.1.12 spark-worker2

Tester la résolution des noms depuis les trois machines :

ping -c 3 spark-master
ping -c 3 spark-worker1
ping -c 3 spark-worker2

En cas d’échec, vérifier les adresses IP, le masque réseau, le routage et le contenu de /etc/hosts.

3.2 Installer Java et Python

Sur chaque machine :

sudo apt update
sudo apt install -y openjdk-21-jdk python3 python3-venv python3-pip openssh-client

Vérifier les installations :

java -version
javac -version
python3 --version
readlink -f "$(which java)"

Le chemin de JAVA_HOME correspond au répertoire Java situé avant /bin/java. Sur une installation Ubuntu AMD64 standard, il peut être :

/usr/lib/jvm/java-21-openjdk-amd64

Vérifier le chemin réel sur chaque serveur avant de le configurer.

4. Installer Apache Spark

Nous utiliserons le mode Standalone, le gestionnaire de cluster intégré à Spark. Il permet de déployer un Master et plusieurs Workers sans installer Hadoop YARN.

Sur chaque serveur, consulter la page officielle de téléchargement Apache Spark. Choisir une version stable compatible avec l’environnement Java/Python du TP et utiliser la même distribution sur les trois machines.

Télécharger l’archive proposée par le site officiel sur les trois machines, ou la transférer depuis une machine de téléchargement. L’exemple ci-dessous suppose que l’archive s’appelle spark-4.2.0-bin-hadoop3.tgz ; adapter le nom au fichier réellement téléchargé.

sudo tar -xzf spark-4.2.0-bin-hadoop3.tgz -C /opt/
sudo ln -sfn /opt/spark-4.2.0-bin-hadoop3 /opt/spark
sudo chown -R "$USER":"$(id -gn)" /opt/spark-4.2.0-bin-hadoop3

4.1 Configurer les variables d’environnement

Sur chaque serveur :

nano ~/.bashrc

Ajouter les lignes suivantes, en adaptant JAVA_HOME au chemin réel :

export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export SPARK_HOME=/opt/spark
export PATH="$PATH:$SPARK_HOME/bin:$SPARK_HOME/sbin"

Appliquer et vérifier :

source ~/.bashrc
echo "$JAVA_HOME"
echo "$SPARK_HOME"
spark-submit --version
Compatibilité : la version de Spark, Java et Python doit être vérifiée sur la documentation officielle correspondant à la version choisie. Si le nom de l’archive ou les versions disponibles diffèrent, adapter les commandes à la distribution effectivement installée.

5. Configurer le réseau et la communication

5.1 Vérifier la connectivité

Depuis le Master :

ping -c 3 spark-worker1
ping -c 3 spark-worker2

Si UFW est actif, les communications doivent être autorisées entre les trois machines sur le réseau local de confiance.

sudo ufw allow from 192.168.1.0/24
Cette règle autorise tout le trafic provenant du sous-réseau indiqué. Elle ne convient qu’à un réseau de TP maîtrisé. En production, limiter les règles aux ports nécessaires et aux adresses des nœuds.
PortFonction
7077/TCPConnexion au Master Spark
8080/TCPInterface Web du Master
8081/TCPInterface Web du Worker 1, par défaut dans ce TP
8082/TCPInterface Web du Worker 2, après configuration
Ports supplémentairesCommunication driver/executors, transferts de blocs et données

Les ports des executors et du driver peuvent être dynamiques. Le pare-feu doit permettre les communications requises entre les nœuds sans exposer les interfaces d’administration à des réseaux non fiables.

5.2 Lancement des Workers

Le TP démarre les Workers manuellement. Cette méthode évite de configurer une connexion SSH sans mot de passe entre le Master et les Workers. Le démarrage distant automatisé par SSH pourra être étudié dans un TP ultérieur.

6. Configurer le Master et les Workers

6.1 Configuration du Master

Sur spark-master :

nano "$SPARK_HOME/conf/spark-env.sh"

Ajouter :

export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export SPARK_MASTER_HOST=spark-master
export SPARK_MASTER_PORT=7077
export SPARK_MASTER_WEBUI_PORT=8080

6.2 Configuration du Worker 1

Sur spark-worker1, créer ou modifier $SPARK_HOME/conf/spark-env.sh :

export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export SPARK_LOCAL_IP=192.168.1.11
export SPARK_WORKER_CORES=4
export SPARK_WORKER_MEMORY=6g
export SPARK_WORKER_WEBUI_PORT=8081

6.3 Configuration du Worker 2

Sur spark-worker2, créer ou modifier le même fichier :

export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export SPARK_LOCAL_IP=192.168.1.12
export SPARK_WORKER_CORES=4
export SPARK_WORKER_MEMORY=6g
export SPARK_WORKER_WEBUI_PORT=8082

Les valeurs de quatre cœurs et 6 Go de mémoire sont des exemples. Les adapter aux ressources de chaque machine. La mémoire annoncée au cluster doit laisser suffisamment de RAM au système d’exploitation.

7. Démarrer le cluster distribué

7.1 Démarrer le Master

Sur spark-master :

start-master.sh
jps

Le processus Master doit apparaître. Ouvrir l’interface Web depuis un navigateur du réseau local : http://192.168.1.10:8080.

L’URL Spark du cluster doit ressembler à :

spark://spark-master:7077

7.2 Démarrer le Worker 1

Sur spark-worker1 :

start-worker.sh spark://spark-master:7077
jps

Le processus Worker doit apparaître.

7.3 Démarrer le Worker 2

Sur spark-worker2 :

start-worker.sh spark://spark-master:7077
jps

7.4 Vérifier le cluster

Revenir sur l’interface Web du Master : http://192.168.1.10:8080.

  • Le Master est actif.
  • Deux Workers sont enregistrés.
  • Les cœurs et la mémoire annoncés par chaque Worker sont visibles.
  • Chaque Worker possède l’état ALIVE.
Validation : le cluster est opérationnel lorsque les deux Workers sont enregistrés auprès du Master et actifs. Le démarrage des processus sur les machines ne suffit pas : leur enregistrement doit être confirmé dans l’interface Web.

8. Préparer le dataset sur les trois machines

Le fichier CSV doit être accessible depuis le driver et depuis les Workers qui exécutent les tâches de lecture. Pour ce TP, la solution simple consiste à copier le même fichier sur les trois machines, au même chemin local.

Lien de téléchargement du dataset : Student Performance Dataset.

8.1 Créer le répertoire

Sur les trois serveurs :

sudo mkdir -p /data/spark
sudo chown "$USER":"$(id -gn)" /data/spark

8.2 Copier le fichier CSV

Supposons que le fichier complet soit disponible sur le Master sous /data/spark/students.csv. Depuis le Master :

scp /data/spark/students.csv \
    "$USER"@spark-worker1:/data/spark/students.csv

scp /data/spark/students.csv \
    "$USER"@spark-worker2:/data/spark/students.csv

Si les noms d’utilisateurs diffèrent, remplacer $USER par le compte approprié pour chaque destination.

Sur chaque machine, vérifier le fichier :

wc -l /data/spark/students.csv
head -n 2 /data/spark/students.csv
sha256sum /data/spark/students.csv

Pour un CSV d’un million d’étudiants avec une ligne d’en-tête, wc -l doit afficher 1000001. Les empreintes SHA-256 des trois copies doivent être identiques.

Remarque : cette méthode suppose que les copies locales sont identiques et restent synchronisées. Pour des volumes plus importants ou un environnement durable, un stockage partagé ou distribué comme HDFS est préférable.

9. Créer l’application PySpark

Sur le Master, créer le répertoire de travail :

mkdir -p ~/td-spark/app
cd ~/td-spark/app
nano students_analysis.py

Enregistrer le programme ci-dessous dans students_analysis.py.

from time import perf_counter

from pyspark.sql import SparkSession
from pyspark.sql.functions import (
    avg, count, col, round as spark_round,
    min as spark_min, max as spark_max, desc
)
from pyspark.sql.types import (
    StructType, StructField, IntegerType,
    DoubleType, StringType
)

spark = (
    SparkSession.builder
    .appName("AnalyseEtudiants")
    .getOrCreate()
)

spark.sparkContext.setLogLevel("WARN")

schema = StructType([
    StructField("student_id", IntegerType(), False),
    StructField("weekly_self_study_hours", DoubleType(), True),
    StructField("attendance_percentage", DoubleType(), True),
    StructField("class_participation", DoubleType(), True),
    StructField("total_score", DoubleType(), True),
    StructField("grade", StringType(), True)
])

# Le CSV existe à ce chemin sur le driver et les Workers.
csv_path = "file:///data/spark/students.csv"

start = perf_counter()

df = (
    spark.read
    .option("header", True)
    .schema(schema)
    .csv(csv_path)
)

print("=== SCHEMA ===")
df.printSchema()

print("=== EXEMPLE DE DONNEES ===")
df.show(10, truncate=False)

print("=== NOMBRE D'ETUDIANTS ===")
total = df.count()
print(total)

print("=== STATISTIQUES GLOBALES ===")
df.select(
    spark_round(
        avg("weekly_self_study_hours"), 2
    ).alias("heures_etude_moyennes"),
    spark_round(
        avg("attendance_percentage"), 2
    ).alias("presence_moyenne"),
    spark_round(
        avg("class_participation"), 2
    ).alias("participation_moyenne"),
    spark_round(
        avg("total_score"), 2
    ).alias("score_moyen"),
    spark_min("total_score").alias("score_minimum"),
    spark_max("total_score").alias("score_maximum")
).show()

print("=== EFFECTIFS ET SCORES PAR MENTION ===")
df.groupBy("grade").agg(
    count("*").alias("effectif"),
    spark_round(
        avg("total_score"), 2
    ).alias("score_moyen")
).orderBy("grade").show()

print("=== LES 10 MEILLEURS ETUDIANTS ===")
df.orderBy(
    desc("total_score")
).select(
    "student_id",
    "weekly_self_study_hours",
    "attendance_percentage",
    "total_score",
    "grade"
).show(10, truncate=False)

print("=== ETUDIANTS EN DIFFICULTE ===")
df.filter(
    (col("attendance_percentage") < 70)
    & (col("total_score") < 50)
).select(
    "student_id",
    "attendance_percentage",
    "total_score",
    "grade"
).show(20, truncate=False)

print("=== CORRELATION HEURES D'ETUDE / SCORE ===")
correlation = df.stat.corr(
    "weekly_self_study_hours",
    "total_score"
)
print(correlation)

print(f"Temps écoulé : {perf_counter() - start:.2f} s")

spark.stop()

Comprendre les principales instructions

InstructionFonction
SparkSession.builderCrée la session Spark de l’application.
spark.read.csv()Charge le dataset CSV.
df.count()Compte les lignes du dataset.
df.select()Sélectionne les colonnes et calcule les statistiques.
df.groupBy()Regroupe les étudiants par mention.
df.filter()Filtre les étudiants selon une condition.
df.orderBy()Trie les étudiants selon leur score.
df.stat.corr()Calcule la corrélation de Pearson.

L’API DataFrame est adaptée aux données structurées. Les agrégations et les tris peuvent provoquer des échanges de données entre executors ; leur coût dépend du volume, du partitionnement et des ressources disponibles.

10. Soumettre l’application au cluster

Depuis le Master, exécuter :

spark-submit \
  --master spark://spark-master:7077 \
  --deploy-mode client \
  --conf spark.driver.host=192.168.1.10 \
  --conf spark.driver.bindAddress=0.0.0.0 \
  --executor-cores 2 \
  --executor-memory 2g \
  --total-executor-cores 8 \
  ~/td-spark/app/students_analysis.py
ParamètreSignification
--masterAdresse du Master auquel l’application se connecte.
--deploy-mode clientLe driver s’exécute sur la machine qui lance la commande.
--executor-cores 2Deux cœurs par executor.
--executor-memory 2gJusqu’à 2 Go de mémoire configurée par executor.
--total-executor-cores 8Limite de huit cœurs d’executor pour l’application.

Avec deux Workers configurés à quatre cœurs chacun, cette configuration vise à utiliser les huit cœurs disponibles. L’allocation effective dépend des ressources réelles et de la planification du cluster.

Pendant l’exécution, consulter :

  • Interface du Master : http://192.168.1.10:8080
  • Interface de l’application Spark : http://192.168.1.10:4040

L’interface de l’application permet de consulter les jobs, stages, tâches, executors et durées d’exécution.

En cas d’échec : vérifier le pare-feu, les adresses IP annoncées, l’accès au fichier CSV sur les Workers et les ports de communication du driver/executors. En mode client, les Workers doivent pouvoir joindre le driver sur le Master.

11. Arrêter le cluster

Sur le Worker 1 :

stop-worker.sh

Sur le Worker 2 :

stop-worker.sh

Sur le Master :

stop-master.sh

Ces commandes arrêtent les démons Spark lancés avec les scripts correspondants. Pour une installation persistante, un TP ultérieur pourra étudier la création de services systemd pour démarrer automatiquement le Master et les Workers après un redémarrage.
